What is a form?

A form is how a website collects information from a visitor: a login box, a signup page, a contact form, a search bar. Without forms, a website can only talk at you. With forms, it can listen.

A form is built with the <form> tag. Everything the visitor fills in goes inside it. Two attributes matter most. The action attribute says where the data goes when the form is submitted — usually a page or a server address. The method attribute says how it is sent: get puts the data in the web address (good for a search form), post sends it hidden in the request (good for logins and signups, because passwords should never appear in the address bar).

<form action="/signup" method="post">
  <!-- inputs go here -->
</form>

In this course the form does not send data anywhere yet — there is no server in version 1. That is fine. You are learning the structure now; in the JavaScript module you will make the form respond on the page itself.

Text inputs

The <input> tag is the workhorse of every form. It is an empty element, and its type attribute decides what kind of field it becomes:

<input type="text" placeholder="Your name">
<input type="email" placeholder="you@example.com">
<input type="password" placeholder="Choose a password">
<input type="number" min="1" max="100">
<input type="date">

The type does more than change the look. type="email" makes the browser check that the text looks like an email address. type="password" hides the letters as dots. type="number" shows up and down arrows on desktop and a number keyboard on phones. On a phone, the right keyboard appears automatically — that is a small detail your visitors will notice.

Two more attributes you will use constantly: placeholder shows a grey hint inside an empty field, and required stops the form from submitting until the field is filled. Always pair an input with a <label>. The label's for attribute must match the input's id — then clicking the label focuses the field, and screen readers can read the form out loud:

<label for="email">Email address</label>
<input type="email" id="email" name="email" required>

The name attribute is the field's name in the data that gets sent. Without a name, the field's value is never sent at all — a common beginner bug.

Choices: checkboxes, radios and dropdowns

Not every answer is typed. Sometimes the visitor picks from choices. A checkbox is for yes-or-no questions and for picking several items from a list:

<label><input type="checkbox" name="topics" value="html"> HTML</label>
<label><input type="checkbox" name="topics" value="css"> CSS</label>

Radio buttons are for picking exactly one option from a group. All the radios in one group share the same name — that is what links them together, so choosing one un-chooses the others:

<label><input type="radio" name="plan" value="free"> Free</label>
<label><input type="radio" name="plan" value="paid"> Paid</label>

For a long list of options, a dropdown saves space. The <select> tag holds the list, and each choice is an <option>:

<label for="city">City</label>
<select id="city" name="city">
  <option value="lahore">Lahore</option>
  <option value="karachi">Karachi</option>
  <option value="islamabad">Islamabad</option>
</select>

The value is what gets sent; the text between the option tags is what the visitor sees. They can be different — for example, value="pk" with the text "Pakistan".

Text areas and the submit button

For longer text — a message, a comment, a description — use <textarea>. Unlike <input>, it has an opening and a closing tag, and the rows attribute sets how tall it is:

<label for="message">Your message</label>
<textarea id="message" name="message" rows="4"></textarea>

Finally, the form needs a way to send. A <button type="submit"> inside the form submits it. A <button type="reset"> clears all the fields — use it rarely, because visitors click it by accident and lose their work. A plain <button type="button"> does nothing on its own; JavaScript gives it a job later.

<button type="submit">Send message</button>

Here is a complete contact form, putting everything together:

<form action="/contact" method="post">
  <label for="name">Name</label>
  <input type="text" id="name" name="name" required>

  <label for="email">Email</label>
  <input type="email" id="email" name="email" required>

  <label for="message">Message</label>
  <textarea id="message" name="message" rows="4"></textarea>

  <button type="submit">Send message</button>
</form>

Exercise — A signup form

Add a signup form to your personal page: a text input for your name, an email input, a password input, a dropdown for your city, one checkbox for 'Send me updates', and a submit button. Make every field required except the checkbox, and give every input a label with a matching for and id. Open the page and try submitting it empty — the browser should stop you and point at the first empty field.
