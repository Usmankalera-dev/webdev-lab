Storing values

A variable is a named box that holds a value. You create one with let or const, give it a name, and store something in it with =:

let age = 20;
const city = "Lahore";
let score = 0;

let is for values that can change — a score that goes up, a name the visitor edits. const is for values that never change — a city name, a price, a maximum number of seats. If you try to change a const, JavaScript stops you with an error, which is exactly the point: it protects you from changing something by accident.

There is also an older keyword, var. You will see it in old code and old tutorials, but modern JavaScript uses let and const — they are safer, because they only exist inside the block where they were created. This course uses let and const only.

Data types

Every value in JavaScript has a type. The five you will use every day are:

let name = "Usman";   // string — text, in quotes
let age = 20;         // number — no quotes
let isStudent = true; // boolean — true or false
let middleName = null;      // null — deliberately empty
let nickname;               // undefined — never given a value

Strings use single or double quotes — pick one and be consistent. Numbers have no quotes: 20 is a number, "20" is a string, and JavaScript treats them very differently (you will see why in a moment). Booleans are only ever true or false — they are the answers to yes-or-no questions, like "is the user logged in?"

When you are unsure of a value's type, ask with typeof:

typeof "Usman";  // "string"
typeof 20;      // "number"
typeof true;    // "boolean"

Working with values

Variables are only useful if you can do things with them. The maths operators are the ones you know: +, -, *, /. And ++ adds one — score++ is short for score = score + 1:

let price = 500;
let quantity = 3;
let total = price * quantity;  // 1500
total = total + 100;           // 1600

Here is the trap with +: when one side is a string, JavaScript joins the values instead of adding them. 5 + "5" is "55", not 10. That is why form inputs — which are always strings — need converting with Number() before you do maths with them:

let typed = "20";
Number(typed) + 5;   // 25, a real number

Template literals make it easy to build sentences from variables. They use backticks (`) instead of quotes, and ${ } drops a value into the text:

let name = "Usman";
let age = 20;
console.log(`My name is ${name} and I am ${age} years old.`);
// My name is Usman and I am 20 years old.

Naming variables

Good names make your code readable. The rules are simple: a name can contain letters, digits, $ and _, but it cannot start with a digit, and it cannot contain spaces or hyphens. By convention, JavaScript names use camelCase — first word lowercase, each later word capitalised: studentName, totalPrice, isLoggedIn.

Names should say what the value is. x tells you nothing; studentCount tells you everything. Some words are reserved by the language — you cannot name a variable let, function or return — but the browser will tell you if you try.

Exercise — A bill calculator

Write a script that stores a price (Rs 500) and a quantity (4) in variables, calculates the total, and prints a sentence with a template literal: 'Total: Rs 2000 for 4 items.' Then change the quantity to 2, recalculate, and print the new total. Try printing price + '5' and see what happens — then fix it with Number().
