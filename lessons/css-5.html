Why responsive?

More than half of all web traffic comes from phones. A website that only looks right on a laptop is a website that fails most of its visitors. Responsive design means one website that adapts to any screen: the same HTML, with CSS that changes the layout as the screen gets smaller.

You have already seen it on this site. Open this lesson on your phone: the navigation collapses into a menu button, the text stays readable, and nothing runs off the edge of the screen. On a laptop, the same page spreads out wider. One file, two experiences — that is responsive design.

The viewport tag

Every responsive page starts with one line in the <head>. Without it, phones pretend to be a 980px-wide desktop screen and shrink the whole page down to fit — tiny text, and the visitor has to pinch and zoom:

<meta name="viewport" content="width=device-width, initial-scale=1.0">

This tag tells the phone: "the page width is the device width, and start at normal zoom". With it, your CSS sees the real screen size — 390px on a phone, 1280px on a laptop — and can respond to it. Every page in this course has this tag. Check any page you build from now on: if it looks tiny on your phone, the viewport tag is the first thing to check.

Media queries

A media query is a CSS rule that only applies when the screen matches a condition — usually its width. It is how you say "on small screens, do this differently":

/* Default: three cards in a row */
.cards { display: flex; gap: 16px; }

/* On screens 700px wide or smaller: stack them */
@media (max-width: 700px) {
  .cards { flex-direction: column; }
  h1 { font-size: 1.8rem; }
}

The rules inside the media query override the normal rules, but only when the condition is true. max-width: 700px means "up to 700px wide" — phones and small tablets. You can also use min-width for "700px and wider". The number you choose is called a breakpoint, and 700px is a good first one: below it, you are probably on a phone.

Flexible layouts

Media queries handle the big changes. For the small ones, use flexible sizes from the start. Percentages grow and shrink with their parent: width: 100% fills the available space, whatever it is. max-width sets a ceiling — max-width: 800px means "800px on a big screen, less on a small one". Together they make a container that is wide on a laptop and full-width on a phone, with no media query needed:

.container {
  width: 90%;
  max-width: 800px;
  margin: 0 auto;
}

Images need one rule too. An image with a fixed width of 600px will overflow a 390px phone screen and force horizontal scrolling — the most common responsive bug. This fixes it:

img { max-width: 100%; height: auto; }

The image never gets wider than its container, and height: auto keeps its proportions. Finally, the mobile-first approach: write the CSS for the phone first, then add media queries for bigger screens with min-width. It is easier to add space as the screen grows than to squeeze a desktop design onto a phone — and since most of your visitors are on phones, the phone layout is the one that matters most.

Exercise — Make your page responsive

Take your personal page and make it responsive: add the viewport meta tag if it is missing, set img max-width: 100%, and add a media query at max-width: 700px that reduces the h1 font size and stacks any row of cards into a column. Test it by shrinking your browser window — the layout should change smoothly, with no horizontal scrolling at any size.
