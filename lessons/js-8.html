The plan

This is the last JavaScript lesson, and it uses everything you have learned. We will build a to-do app: type a task, click Add, and it appears in a list. Each task has a delete button, and clicking the task marks it done. The tasks survive a page refresh, because they are saved in the browser.

The plan has four parts. First, the HTML: an input, an Add button, and an empty list. Second, an array that holds the tasks. Third, a render() function that draws the list from the array. Fourth, saving the array in localStorage so it survives a refresh. When the data changes, we save it and re-draw the list — one pattern for the whole app.

<input id="taskInput" placeholder="New task...">
<button id="addBtn">Add</button>
<ul id="taskList"></ul>

Adding a task

When the Add button is clicked, we read the input, add the task to the array, clear the input, save, and re-draw:

let tasks = [];
let input = document.getElementById("taskInput");
let list = document.getElementById("taskList");

document.getElementById("addBtn").addEventListener("click", function () {
  let text = input.value.trim();
  if (text === "") return;  // ignore empty tasks
  tasks.push({ text: text, done: false });
  input.value = "";
  saveAndRender();
});

Each task is an object with two properties: the text and whether it is done. The trim() call removes spaces from both ends, so a task of only spaces is treated as empty. The guard if (text === "") return; stops empty tasks from being added at all.

Drawing the list

The render() function clears the list and rebuilds it from the array. For each task it creates an <li>, a text span, and a delete button, and attaches the right behaviour to each:

function render() {
  list.innerHTML = "";
  tasks.forEach(function (task, index) {
    let li = document.createElement("li");
    li.textContent = task.text;
    if (task.done) li.classList.add("done");

    li.addEventListener("click", function () {
      task.done = !task.done;
      saveAndRender();
    });

    let del = document.createElement("button");
    del.textContent = "Delete";
    del.addEventListener("click", function (e) {
      e.stopPropagation();
      tasks.splice(index, 1);
      saveAndRender();
    });
    li.appendChild(del);
    list.appendChild(li);
  });
}

Two details matter. First, document.createElement("li") builds a new element in JavaScript, and appendChild puts it on the page. Second, the delete button's handler calls e.stopPropagation() — without it, clicking Delete would also trigger the list item's click handler and mark the task done just before deleting it. Events bubble up from the button to the list item, and stopPropagation stops that.

splice(index, 1) removes one item at a given position from the array. And task.done = !task.done flips the done flag — ! turns true into false and false into true.

Saving with localStorage

Without saving, the tasks vanish on refresh. localStorage is a small storage area in the browser — the same one this course uses for your lesson progress. It only stores strings, so we convert the array to JSON text when saving, and parse it back when loading:

function saveAndRender() {
  localStorage.setItem("todo-tasks", JSON.stringify(tasks));
  render();
}

let saved = localStorage.getItem("todo-tasks");
if (saved) tasks = JSON.parse(saved);
render();

JSON.stringify turns the array into a string; JSON.parse turns the string back into an array. On page load, we read the saved string — if there is one — and draw the list from it. Add a task, refresh the page, and it is still there. You have just built a complete app: input, storage, rendering, and events, in about forty lines. That is what this whole module was for.

Exercise — Finish the app

Build the full to-do app from this lesson in one HTML file, with a little CSS to make done tasks show a line through them (a .done class with text-decoration: line-through). Then add one feature of your own: a 'Clear completed' button that removes all done tasks, or a counter that shows how many tasks are left. Test it, refresh the page, and confirm your tasks are still there.
