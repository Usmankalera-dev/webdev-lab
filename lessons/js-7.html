What is an API?

So far, all your data has lived inside your own code. But real websites get their data from somewhere else: weather from a weather service, posts from a server, prices from a shop's database. An API (Application Programming Interface) is a web address you can ask for data, and it answers with data instead of a web page.

For example, https://jsonplaceholder.typicode.com/posts/1 is a free practice API. Open it in your browser and you will see raw data — a post with a title and a body — instead of a designed page. Your JavaScript can ask for that same address, get the data, and show it on your page in your own design.

fetch() and promises

JavaScript asks for data with fetch(). You give it a web address, and it returns a Promise — an object that says "I do not have the answer yet, but I will". The data takes time to travel over the internet, so JavaScript does not wait: it carries on, and the promise delivers the answer when it arrives:

fetch("https://jsonplaceholder.typicode.com/posts/1")
  .then(function (response) {
    console.log(response);
  });

.then() means "when the answer arrives, run this function with it". The first answer is a response object — it tells you the status (200 means OK) and carries the data. But the data is still in raw text form, so you need one more step.

Reading JSON

APIs almost always answer in JSON — JavaScript Object Notation. JSON looks like a JavaScript object, and that is no accident: it was designed to be easy for JavaScript to read. response.json() reads the body and turns it into a real object you can use:

fetch("https://jsonplaceholder.typicode.com/posts/1")
  .then(function (response) {
    return response.json();
  })
  .then(function (post) {
    console.log(post.title);
    console.log(post.body);
  });

Two .then() steps: the first gets the response and returns its JSON, the second receives the finished object. post.title is now a normal string you can put on the page with textContent, exactly like in Lesson 14. That is the whole pattern: fetch, read JSON, use the data.

One rule: fetch only works on pages served over HTTP — it will fail if you open your HTML file directly from your computer with file://. Use a local server (for example python3 -m http.server) or a hosted page like this one, and it works.

async and await

Chained .then() calls work, but they get hard to read when there are several steps. async and await are a cleaner way to write the same thing. await pauses the function until the promise finishes — the code reads top to bottom, like normal code:

async function loadPost() {
  let response = await fetch(
    "https://jsonplaceholder.typicode.com/posts/1"
  );
  let post = await response.json();
  console.log(post.title);
}

loadPost();

The function must be marked async for await to work inside it. The page does not freeze while it waits — only this function pauses; everything else keeps running. Use async/await for new code, and recognise .then() when you see it in older code. Both do the same job.

Exercise — Show a post on your page

Make a page with an h2 and a paragraph with ids. Write an async function that fetches post 1 from https://jsonplaceholder.typicode.com/posts/1, reads it as JSON, and puts the post title in the h2 and the body in the paragraph. Serve the page with python3 -m http.server and open it through http://localhost:8000 — then change the URL to /posts/2 and watch the content change.
